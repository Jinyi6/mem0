# 搜索模式性能差异分析报告 (Mode 0 vs Mode 14.10)

## 核心结论
尽管 Mode 14.10 设计更为复杂（包含意图识别、多跳检索等），但在当前数据集 Evaluation 中表现显著不如简单的 Mode 0。这主要归因于 **"信息过载悖论" (Information Overload Paradox)**：Mode 14.10 检索到了更多（包括过时或矛盾）的信息，但 Answer LLM 无法有效处理这些冲突，反而被误导；而 Mode 0 由于检索能力较弱，往往只命中单一（且恰好是正确的）信息，反而避免了混淆。

此外，**检索排序的偏差** 也是导致 Mode 14.10 得分较低的重要原因。

---

## 详细原因分析

### 1. 信息过载与冲突消解失败 (Information Overload & Conflict Resolution Failure)
Mode 14.10 经常能同时检索到 "旧事实" 和 "新事实"，但 LLM 在回答生成阶段未能遵循 "以最新时间为准" 的原则，反而被旧记忆中更明确的措辞所吸引。

*   **典型案例：5K 跑步个人最好成绩 (Personal Best)**
    *   **现象：** 用户在 5/23 设定了 "27:12" 的 PB，随后在 5/30 表示 "目标是打破 25:50 的 PB"。
    *   **Mode 0 (正确)：** 仅检索到 5/30 的记忆，直接得出 25:50。
    *   **Mode 14.10 (错误)：** 同时检索到了两条记忆。LLM 进行了过度推理，认为 "目标是打破" 意味着 "还没达到"，因此判定 27:12 才是 "已确认的" PB，从而忽略了时间上的先后推断（即 5/30 的陈述暗示了 PB 已更新）。
    *   **结论：** 更多的上下文反而导致了错误的推理路径。

### 2. 语义歧义与颗粒度混淆 (Ambiguity & Granularity Mismatch)
Mode 14.10 有时会混淆 "具体的习惯" 和 "一般性的事件"，导致回答的颗粒度不符合预期。

*   **典型案例：瑜伽频率 (Yoga Frequency)**
    *   **现象：** 早期记忆显示 "每周三次 (Mon/Wed/Fri)"，近期记忆提到 "每周一次的瑜伽课 (weekly yoga class)" 作为社交承诺。
    *   **Mode 0 (正确)：** 抓住了 "每周三次" 的具体细节。
    *   **Mode 14.10 (错误)：** 抓住了最新的 "weekly" 描述，回答 "每周一次"，忽略了 "每周三次" 是更具体的锻炼习惯，而 "weekly class" 可能只是其中一部分。
    *   **结论：** 对 "频率" 的理解偏差，过度偏向最新的（但可能是片面的）概括性描述。

### 3. 核心信息检索遗漏 (Critical Retrieval Misses)
尽管 Mode 14.10 更复杂，但在某些简单事实的检索上反而出现了 "灯下黑"，可能是由于 Query 重写或 Keyword 扩展引入了噪音，挤占了核心记忆的排序位置。

*   **典型案例：通勤时间 (Commute Time)**
    *   **现象：** 正确答案是 "45分钟"。
    *   **Mode 0 (正确)：** 检索到了包含 "45 minutes" 的记忆。
    *   **Mode 14.10 (错误)：** 检索到了关于 "骑车通勤 (10 miles)" 的记忆，完全遗漏了 "45分钟" 的关键信息。
    *   **结论：** 复杂的检索策略（如关键词扩展）可能在这类简单问题上产生了负面效果，导致核心关键词（"45 minutes"）权重下降。

### 4. 过度推理与评估偏差 (Over-Reasoning & Evaluation Strictness)
部分 Mode 14.10 的 "错误" 实际上是由于回答过于详尽或格式不匹配导致的，在人工评估中可能算作正确或部分正确，但在严格的自动化评估中被判错。

*   **典型案例：最近的交通方式 (Train vs Bus)**
    *   **现象：** 问题是 "最近一次坐火车是什么时候"。
    *   **Mode 0 (正确)：** 直接回答 "3月3日"。
    *   **Mode 14.10 (判错)：** 给出了详细的对比推理："3月3日的火车比2月27日的巴士更近，所以是3月3日..."。
    *   **结论：** 虽然逻辑正确，但因为包含冗余信息或格式问题被判错。
*   **典型案例：毕业学位 (Graduation Degree)**
    *   **现象：** Mode 14.10 回答非常详细（包含完整学位名），但可能因为 Evaluate 脚本期待简短答案而被标记为 False Positive。

## 2. 两种 search mode 的整体风格差异

### 2.1 search mode 0（朴素向量检索）

从这 51 题里能看出来的特点：

1. **更“宽松”，召回更高**

   * 只看语义相似度，很多时候会把“刚好含有答案的那条记忆”拉进来。
   * 比如：

     * Q00：「我在社区剧院看的是哪部话剧？」
       mode 0 的 top memories 里有一条直接写着 *“The Glass Menagerie”*；
     * Q01：之前的姓氏？
       top memory 直接是 *“changed last name from Johnson to Winters”*；
     * Q02：Spotify 播放列表名？
       有 *“playlist called 'Summer Vibes'”*；
     * Q03：之前职业？
       有一条 *“previously worked as a marketing specialist at a small startup”*。
   * 在这些情况下，LLM 很容易读到这句然后照抄答案。

2. **对“语义相关但不完全匹配”的情况比较友好**

   * 有些题答案并不是一条记忆里干净地写出来，而是要结合两三条。
   * 例：Q05「留学在哪个学校」，记忆里是：

     * “去 Great Ocean Road in Australia during study abroad”
     * “got accepted into University of Melbourne’s master program”
       LLM 能推断出：“留学是去 University of Melbourne in Australia”。

3. **有一点“能猜就猜”的倾向**

   * 在某些题里，记忆并不精确覆盖答案，但 mode 0 尽量根据已有信息给出一个合理的回答；
   * 例如一些建议类/偏策略题（Q10、Q11、Q12、Q13），它会用“用户偏好 + 普通知识”凑出合理回答。
   * 对你的评分逻辑来说，这种“合理但不胡编”的回答往往被判对或给高分。

> 简单说：**mode 0 更像“搜索引擎 + 聪明但不太保守的 LLM”。召回高，噪声也多，但很多题只要召回到那一条关键记忆，LLM 就能搞定。**

---

### 2.2 search mode 14.10（复杂检索策略）

从检索结果的内容看，有很明显的几个特征：

1. **特别偏向“某些高权重事件”**

   * 很多题里都会看到重复出现的一小撮记忆，比如：

     * 2023/05/23 足球比赛；
     * 2023/05/26 coffee table 到货；
     * 2023/05/29 LA 自驾；
     * 2023/06/16 鸡尾酒课；
     * 2023/05/24 看医生；
     * 2023/05/30 Roscioli 订位……
   * 不管问题是在问剧院、Spotify、健身房还是旅行餐厅，14.10 都非常爱把这几个“核心事件”放进上下文。

2. **时间/重要性过滤过于激进**

   * 很多题问的是某个具体 fact（姓名、次数、地点），而对应的记忆明明离“现在”也不远（比如一周内），但 14.10 仍然没把它选进来。
   * 例如：

     * Q00（剧院的话剧）、Q01（旧姓）、Q02（Spotify 列表名）、Q03（旧职业）、Q06（IKEA 组装时长）等等，
       mode 0 都有那条非常具体的记忆，14.10 却完全没召回。

3. **回答风格明显比 mode 0 更“保守”**

   * 很多情况下，14.10 会说：

     * “memories provided do not mention … so there is no answer”
   * 即使它的上下文里其实已经有相关信息（比如含有“20 playlists”、“Data Science certification”之类的句子），它也会倾向于认定“没有足够信息”，从而回答“无法确定”。

4. **在一个少数子集上确实更强**

   * 比如：

     * Q20「我几天前认识 Emma」：
       两边都找到了 2023/04/11 的记忆，但

       * mode 0 只给出了日期；
       * 14.10 正确算出了“9 天前”这种相对时间。
     * Q25「为了缓解焦虑，我多久去一次瑜伽课」：

       * 14.10 更偏向用最近一条显式描述频率的记忆，得到“每周三次”，和 ground truth 对齐；
     * Q26「慈善 5K 的个人 PB」：

       * 14.10 也能更稳定地选中带 “25:50” 的那条，而 mode 0 在解释时被你评分逻辑判为 0 分。

> 总结一句：**14.10 像是“加了一大堆 heuristics 的高精度检索 + 超保守回答策略”，结果“精度没上去，召回先死了”，在大多数题上反而比简单向量检索差。**

5. **Q14 – 几周前跟姑姑见面并收到吊灯？（4 周）**

   * 时间信息在两边记忆中都很清楚。
   * mode 0 正确算出相对时间；
   * 14.10 明明有信息，却还是给了一个被你判错的答案或干脆认定没法算。

其余如 Q16, Q17（多与物品数量/某个活动次数相关）、Q39（龙与地下城里的木乃伊数量）、Q40（Vatican 附近那家擅长腌肉/cheese 的店名），现象都类似：
**14.10 不缺证据，但要么被噪声淹没，要么在“严格遵守不胡编”的 prompt 下太保守。**

---

### 类型 C：两边的记忆都没直接出现答案，但 mode 0 仍答对，14.10 答错

> **靠推理/偏好/开放式回答，mode 0 更“会说人话”**

这类题多是开放式或习惯/偏好/策略类：

**Q05, Q10, Q11, Q12, Q13, Q15, Q18, Q19, Q21, Q22, Q24, Q35, Q42**

典型模式：

* 这些题的标准答案本身不是一句“事实记忆”，更多是“根据记忆总结出的行为模式或回答风格要求”；
* 例如“你更喜欢哪一类建议”“你不希望助手乱编哪些内容”等；
* 所以在纯字符串层面，两边检索中都“没有包含完整答案句子”。

代表例：

1. **Q10 – 请给我一些配得上当前摄影器材的配件建议（但答案要求：只建议索尼兼容、高质量、不推荐杂牌便宜货）**

   * 记忆里更多是“用户买了某些设备、关心耐用、偏好某品牌”之类，没有一条直接写出最终“政策式答案”。
   * mode 0 在回答时，会综合这些偏好，给出“只推荐与现有品牌兼容、质量好的配件”的风格，被你评分为正确。
   * 14.10 的回答则不完全满足你设计好的“偏好约束”，因此被判 0 分。

2. **Q11 – 推荐本周末周边文化活动（答案要求：不要乱编具体活动，而是说没信息 + 提醒用户可以去哪些渠道查，偏向语言练习/文化交流的活动）**

   * 记忆只告诉我们“你以前参加过某些文化节/音乐节，想多参加类似活动”，没有这周末具体安排。
   * mode 0 的回答是：说明没有记忆中的具体活动，不胡编，只给一些方向性建议，这符合 ground truth。
   * 14.10 可能给出了太具体的虚构活动，或没有正确表达“没有记录”，被判错。

3. **Q12 – 邀同事来家里聚餐，问“烘焙什么好？”（考验的是基于你已有的烘焙经验来给建议）**

   * 记忆中是你过去做过的甜点、成功经验等。
   * mode 0：参考已有烘焙经历，提出与过去经验一脉相承的建议；
   * 14.10：可能忽略了这些记忆，只给了一些 generic suggestion，被评分逻辑判为“不利用记忆”。

4. **Q13 – 周日团骑时车子表现更好，可能原因？**

   * 记忆包含你最近保养、自行车升级、训练状况等。
   * mode 0 利用这些信息提出“可能因为最近维护/升级/训练更系统”等推断；
   * 14.10 可能给了一个与已有记忆不匹配的解释，得分较低。

其它类似（Q15 计算两个博物馆参观之间天数、Q18、Q19、Q21、Q22、Q24、Q35、Q42 多是偏“行为总结/阅读理解”类）：

> 总体现象是：**在非单一 fact、需要做总结/根据偏好作答的题目上，mode 0 更“顺着记忆说话”，14.10 更容易或忽略记忆、或给出太模板化的答复，于是被评分逻辑判错。**

---

### 类型 D：两边记忆都包含答案，但 mode 0 被判错，14.10 被判对

> **极少数 14.10 真正占优 / 或评分噪声**

这类题：**Q23, Q49, Q50**

特点：

* 这三题其实 **两种检索都不差**，都能拿到关键记忆；
* 差别在于回答形式/细节，更贴近你设定的 ground truth。

例子：

1. **Q23 – 我最近坐的是 bus 还是 train？（train）**

   * 两边记忆里都有“最近一次长途是 3 月 3 日坐火车”“更早一次是 bus”。
   * 两个回答都说“train”；mode 0 的长解释被打了 0 分，14.10 得到了 1 分，很可能是评分脚本更偏向简洁直接的回答。
   * 这里更像是评测 noise，而不是检索本身的差异。

2. **Q49 – 我毕业时拿的是什么学位？（Business Administration）**

   * 两边都找到了提到你本科/硕士专业的记忆。
   * 14.10 更精准说出 “degree in Business Administration”；
   * mode 0 可能给了一个不那么精确的说法（比如提到学校、但没提到专业）而被判 0 分。

3. **Q50 – 我每天通勤多长时间？（45 分钟单程）**

   * 记忆里有“commute takes about 45 minutes each way”。
   * 14.10 明确回答“45 minutes each way”；
   * mode 0 可能只说“45 minutes”而没指明“each way”，或者给了往返时长，被你的规则判为不精确。

---

### 类型 E：mode 0 正确，14.10 错误，且两边都没有直接答案字符串

> **多发生在行为趋势/频率类问题，14.10 倾向说“没法确定”**

这类题只有一个特殊例子：**Q30 – “我现在比以前更常去健身房吗？”**

* mode 0：✅

  * 尽管记忆里没有一句话显式写出“你之前每周去 X 次，后来每周 Y 次”，但有若干条描述你从“偶尔去”→“计划每周三次”等。
  * mode 0 结合这些信息，给出“是的，现在更频繁去健身房”的判断。
* 14.10：❌

  * 上下文多是跑步、别的活动；
  * 回答非常保守，说“没有明确比较频率的信息，没法判断”，被判错。

这里能看出 14.10 的一个典型问题：**只会在看到完全“证据链闭合”的情况下才愿意断言“是/否”，而你的 ground truth 把“合理推断”也当作正确。**

---

### 类型 F：mode 0 错误，14.10 正确，且两边检索都能看到答案相关信息

> **14.10 在复杂时间/频率/数值题上稍强**

这类题的代表已经在前面提过：**Q20, Q25, Q26**：

* Q20：算“几天前认识 Emma”，14.10 用相对时间算对了天数；mode 0 偏向重叙述日期/或解释不符评分格式。
* Q25：综合多条关于瑜伽课频率的记忆，14.10 更好地使用了最新的信息给出“每周三次”；mode 0 更含糊。
* Q26：慈善 5K 的 PB，14.10 更稳定地锁定了含 “25:50” 的那条；mode 0 在解释中可能混入了其它跑步成绩，被评分逻辑判为 0 分。

---

## 4. 总体回答你的问题：“为什么复杂检索反而更差？”

综合上面的逐题分析，可以归纳成几个关键点：

1. **14.10 的召回策略过于激进 + 偏向少数高权重记忆**

   * 很多非常关键的“事实记忆”（姓名 / 次数 / 具体地点 / 电话 / 店名）在 14.10 的检索结果中直接消失；
   * 反复出现的却是那几条“看医生 / 鸡尾酒课 / 5 月某次活动”等高权重事件；
   * 对于“我问的是别的事”的题，这就等于 **检索阶段就已经输了**。

2. **14.10 的回答风格太“怕犯错”，宁可说“没记忆”**

   * 即使检索结果里出现了与答案高度相关的记忆，它也经常直接说“没有提到 X，所以无法回答”；
   * 相比之下，mode 0 更乐于“从已有事实中做合理外推”，而你的评测标准正好是鼓励这种合理外推（只要不胡编具体事实）。

3. **复杂 heuristics 与任务指标不匹配**

   * 你设计 14.10 时，很可能在考虑：

     * 时间对齐、事件“重要性”、去重、压缩等；
   * 但当前这套任务的指标更关心：

     * “能不能找到那一条具体 fact，把它喂给 LLM 并让它照着回答出来”；
   * 因此 14.10 虽然理论上更“精细”，但在这个任务上，**召回率的损失远大于精度的收益**。

4. **评测脚本对“形式”也有偏好**

   * 少数题（比如 Q23）中，两边实际语义一样，但一种写法更贴近 ground truth，被判对；
   * 在这种情况下，检索策略本身的差异其实不大，但在总体统计里仍然会贡献到“41 vs 89”的数字。

---

## 5. 两个检索模式的优劣小结（结合这份实验）

**search mode 0（朴素向量检索）**

* ✅ 优点

  * 召回率高，关键 fact 出现的概率更大；
  * 对需要“从多条记忆里稍微推理”的题更友好；
  * 回答风格更愿意给出“合理推断”，符合你当前评测逻辑。
* ❌ 缺点

  * 噪声也多，有时会把若干相似事实混起来（比如多个不同的跑步成绩）；
  * 个别题在精确度/格式上不如 14.10。

**search mode 14.10（复杂检索）**

* ✅ 优点

  * 在少量复杂时间/频率/数值题上，配合更严格的推理规则，能得到更精确的答案；
  * 对“不要胡编”的控制更强。
* ❌ 缺点（也是准确率大跌的主因）

  * 召回极不稳定，许多问题压根检索不到关键记忆；
  * 即使有证据，也经常因为过度保守或被噪声干扰而放弃使用；
  * 偏爱小部分“高权重事件”，导致大量“长尾细节”完全被忽视。

---

如果你后面打算优化 14.10，我建议的方向是：

1. **先确保召回不过度丢信息**：宁可多一点噪声，也要保证“所有可能含答案的记忆都在 top-K 里”；
2. **然后再在 answer 阶段做“基于证据的过滤”**：让 LLM 读所有记忆，但在“最后一跳”里严格引用和交叉检查，而不是在检索阶段就过度剪枝；
3. **对那些“行为风格题”（建议/偏好/不要胡编）单独设计打分和 prompt**，不要和“事实问答”完全混在一起用同一套 heuristics。
